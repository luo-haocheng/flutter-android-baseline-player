# 极简 Demo 落地手册（无代码版）

> 目标：只验证路线，不做产品。
>
> Demo 范围：一个页面、一个本地视频、一个播放器，支持播放/暂停、seek、倍速。
>
> 不做：网络、HLS、多播放器、全屏、画中画、字幕、DRM、后台播放、进度平滑插值、插件化。

---

## 最终交付物

| 部分 | 作用 |
|---|---|
| Flutter 播放页面 | 显示视频区域、播放按钮、进度条、倍速菜单、状态文字 |
| PlatformView 包装 | 把 Android 原生 PlayerView 嵌进 Flutter 页面 |
| 原生 SimplePlayer | 创建 ExoPlayer，加载固定视频，处理控制命令，回传状态 |
| 本地视频资源 | 固定打包在 Android assets 中，不依赖网络 |
| 两个通道 | 一个下发控制命令，一个回传播放状态 |

整个 Demo 只有一个播放器，不需要播放器编号，也不需要管理多个播放器实例。

---

## 第 0 步：准备工程和视频

### 实现功能

- 创建一个 Flutter Android 工程，确认包名和 Kotlin 目录一致。
- 准备一个短的、H.264 + AAC 编码的 MP4 视频。
- 把视频放到 Android 的 assets 目录，而不是 Flutter 的 assets 目录。
- 加入 Media3 ExoPlayer 和 Media3 UI 两个依赖。
- 不需要网络权限，因为视频是本地资源。

### 验证能力

- Flutter 模板工程能正常启动。
- 加入依赖后工程能正常编译。
- 视频文件确实位于 Android assets 目录，文件名和后续加载路径一致。
- 不需要申请存储权限或网络权限。

### 通过标准

工程能编译、能启动，视频资源已就位。  
如果这一步不通过，不要开始写播放器。

---

## 第 1 步：让原生播放器先出画面

### 实现功能

- 在 Android 侧创建一个 ExoPlayer 实例。
- 固定加载 assets 中的本地视频，并开始准备。
- 临时开启自动播放，方便验证画面。
- 创建 PlayerView，关闭它自带的控制条。
- 配置 PlayerView 使用 SurfaceView、保持视频比例、黑底显示。
- 创建 PlatformView 和对应的 Factory，把 PlayerView 交给 Flutter。
- 在 MainActivity 中创建唯一的播放器实例，并注册 PlatformView。
- Flutter 侧只放一个 NativeVideoView，不加按钮和进度条。
- Activity 退到后台时暂停；销毁时释放播放器。

### 验证能力

- ExoPlayer 能正确读取本地 assets 视频。
- 解码后的视频能写入 Surface。
- PlayerView 能通过 PlatformView 显示在 Flutter 页面中。
- 视频比例、黑边、声音正常。
- 退出 App 后声音停止，没有播放器泄漏。

### 通过标准

进入页面能看到视频自动播放，有声音，比例正常，退出后没有声音残留。  
这一步验证的是“解码 + Surface + PlatformView”这条画面链路。

### 失败时先查

- 视频文件是否真的在 Android assets 目录。
- 文件名是否完全一致。
- 视频编码是否是设备支持的 H.264/AAC。
- PlayerView 是否使用 SurfaceView。
- Flutter 是否使用 PlatformView 的 Hybrid Composition 方式。
- Android 日志中是否有资源找不到、解析失败或 Surface 相关错误。

**第 1 步没通过，不要做控制通道。**

---

## 第 2 步：只做 Flutter 到 Android 的控制命令

### 实现功能

- 建立一个 MethodChannel，专门接收 Flutter 下发的命令。
- 原生支持四个命令：播放、暂停、seek 到指定毫秒、设置倍速。
- 播放：让 ExoPlayer 开始播放。
- 暂停：让 ExoPlayer 暂停。
- seek：把播放位置跳到指定时间，并限制不能小于 0。
- 倍速：把播放速度限制在合理范围，例如 0.5 到 2.0 倍。
- 暂时关闭自动播放，改由 Flutter 主动下发播放命令。
- Flutter 页面先放几个临时按钮，不做正式 UI，也不接收状态。

### 验证能力

- Flutter 能调用到 Android 原生方法。
- 播放命令能让视频从暂停状态开始播放。
- 暂停命令能让画面停住，再播放能继续。
- seek 命令能让画面跳到指定位置。
- 倍速命令能明显改变播放速度。
- 暂停状态下 seek，画面也能更新到目标位置。

### 通过标准

四个命令都能通过 Flutter 按钮影响原生播放器。  
此时按钮图标不会自动变化，这是正常的，因为还没有状态回传。

### 失败时先查

- 通道名称在 Flutter 和 Android 两侧是否完全一致。
- 原生是否真的注册了 MethodChannel。
- Kotlin 改动后是否重新完整运行了 App。
- 控制命令的参数名称是否一致。
- Android 日志中是否有找不到播放器或参数错误。

**第 2 步没通过，不要做状态回传。**

---

## 第 3 步：做 Android 到 Flutter 的状态回传

### 实现功能

- 监听 ExoPlayer 的播放状态变化。
- 每 250 毫秒生成一次完整状态快照。
- 建立一个 EventChannel，把状态持续推给 Flutter。
- 状态快照包含：播放状态、当前位置、总时长、是否正在播放、用户是否想播放、当前倍速。
- 播放状态收敛为四种：空闲、缓冲中、可播放、已结束。
- 播放错误单独作为错误事件发送。
- Flutter 订阅事件流，先把状态显示成一行调试文字。
- Flutter 根据用户是否想播放来决定按钮图标，根据是否缓冲决定转圈。

### 验证能力

- 播放时位置数字持续变化。
- 暂停后位置数字停止变化。
- 缓冲时能收到“缓冲中”状态。
- 播放结束时能收到“已结束”状态。
- 改变倍速后，回传的倍速值同步变化。
- 视频加载失败时，Flutter 能收到错误事件。
- 区分“用户想播放”和“当前真的在出帧”，避免缓冲时按钮图标错误。

### 通过标准

Flutter 能持续看到真实播放状态，状态与视频实际行为一致。  
此时还不要求 UI 好看，只要求数据正确。

### 失败时先查

- EventChannel 的监听回调是否被触发。
- 原生是否保存了事件发送端。
- 事件是否在主线程发送。
- 原生定时器是否真的在每 250 毫秒执行。
- Flutter 是否真正订阅了事件流。
- 错误是否被当成普通事件发送，而不是直接关闭事件流。

## 第 4 步：做最小 Flutter 控制界面

### 实现功能

- 视频区域：固定 16:9，放在页面上方。
- 播放/暂停按钮：根据“用户是否想播放”切换图标。
- 重播：播放结束后，点击按钮先回到 0，再播放。
- 进度条：显示当前位置和总时长；拖动时只更新本地显示，松手才下发 seek。
- 时间文字：当前时间 / 总时长。
- 倍速菜单：提供 0.5、1.0、1.5、2.0 四档。
- 缓冲提示：缓冲中显示转圈或进度条。
- 错误提示：显示错误文字，不做自动重试。
- 状态文字：临时显示播放状态，方便验收，最后可以删掉。

### 验证能力

- 按钮能正确反映播放/暂停状态。
- 缓冲时按钮仍显示“暂停”，同时显示缓冲提示。
- 拖动进度条松手后，视频跳转到目标位置。
- 播放结束后显示重播，点击后从头播放。
- 倍速菜单切换后，播放速度和菜单显示同步。
- 暂停状态 seek 后，画面更新。
- 进度条每 250 毫秒更新一次，允许有轻微跳动，Demo 不要求平滑插值。

### 通过标准

不看日志，只通过页面就能完成播放、暂停、seek、倍速四件事。  
这就是 Demo 的核心验收点。

## 第 5 步：收尾和稳定性验证

### 实现功能

- App 退到后台时暂停播放。
- 页面销毁时解绑 PlayerView 和 Surface。
- Activity 销毁时释放 ExoPlayer。
- 删除或隐藏调试用的状态文字。
- 保留最基本的错误提示。
- 不做全屏、不做横竖屏切换、不做后台音频。

### 验证能力

- 按 Home 键后声音停止。
- 回到 App 后可以继续播放。
- 退出页面或退出 App 后没有声音残留。
- 连续进入、退出播放页多次，不会崩溃或叠加声音。
- 快速连点播放/暂停不会崩溃。
- 连续拖动进度条不会卡死。
- 本地视频播放结束后能重播。

### 通过标准

核心功能稳定，没有声音残留和崩溃，Demo 完成。

## 实施顺序总结

| 步骤 | 实现什么 | 验证什么 | 不通过时不要做什么 |
|---|---|---|---|
| 0 | 工程、视频、依赖 | 能编译、资源就位 | 不要写播放器 |
| 1 | ExoPlayer + PlayerView + PlatformView | 视频能显示 | 不要写控制通道 |
| 2 | Flutter 到 Android 的控制命令 | 四个控制能生效 | 不要写状态回传 |
| 3 | Android 到 Flutter 的状态回传 | 状态数据正确 | 不要写正式 UI |
| 4 | 最小控制界面 | 页面上能完成四件事 | 不要做扩展功能 |
| 5 | 生命周期和释放 | 无声音残留、无崩溃 | 不要急着产品化 |

---

## 这个 Demo 明确不验证的东西

- 网络视频和 HLS/DASH；
- 多个视频同时播放；
- 全屏和横竖屏；
- 画中画和后台播放；
- 字幕、音轨、DRM；
- 视频圆角、滤镜、截图；
- 进度条 60fps 平滑插值；
- 错误自动重试；
- 插件化和跨项目复用。

这些都不是当前路线验证的必要条件。  
**只要第 1 到第 4 步通过，就说明 Flutter + Android 原生 ExoPlayer 这条路线可行。**
